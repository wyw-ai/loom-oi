## 使用顺序

1. 读取对应manifest、cases和inputs，将真实版本/拓扑/权限/工具链及隔离记录填入运行前副本；未知值保留null，不以合成ID或请求回显冒充实际实例。
2. 先做材料自检：`python experiments/check_materials.py`。检查文件、输入与判别条件，不运行网络/设备/产品，也不改变任何门槛。
3. 检查运行前置：`python experiments/check_materials.py --ready R1`或`--ready R2`。缺少字段返回2；返回0也只证明记录完整，仍须实际核验隔离、权限、版本和阶段条件。
4. 固定对照、顺序/重复与预算，建立实际运行manifest。当前run.py仅支持LAB-001/002固定夹具，**不要直接把本计划送入runner**；为真实组合开发/审阅适配驱动后遵循既有证据目录协议，保留所有失败。
5. 正确性看提供方真实输入/动作与OI传输记录，质量/性能看独立预注册指标。运行后立即执行raw核验、综合分析、Issue/图文回写和ITER记录，再评适用门槛。

`argv_probe.py`只打印实际进程参数、工作目录及专用标签，不执行输入、不读业务秘密、不提供网络服务。它可由隔离执行服务调用；不能代替执行服务、MCP、OI或桌面。单测只证明该测试材料不会把参数当命令执行。

## 判别与停止

R1三组分别观察包装、工具与OI收益；若结构化直连已解决问题而OI未增加所需发现/授权/可达价值，收紧价值主张。R2按资源实际关系分组，不要求无冲突资源统一加锁；如果无法约束所有入口或证明旧执行器静止，当前共享仲裁方案不满足交接条件。任一越权、串目标或隐式业务重放即为该判别失败，不能用总体成功率抵消。

执行前资源上限、取消窗口、时延/质量预算和重复数由真实环境决定，当前未编造数值。R1/R2测试准备获授权不等于项目承诺维护完整工具包或支持所有设备。产品准入默认和存储细节仍分别在#3/#4评审。
