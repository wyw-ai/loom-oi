## 4. 测试和覆盖率

提前明确固定交付单元的源码范围、指标、排除项及测试命令。保存真实单元测试命令、版本、环境、原始报告及总体分子/分母，门槛≥95%；不添加每模块独立95%的规则，不用混合E2E报告替代。

结果、报告路径和源码/测试/策略指纹放在task.json的verification。初始为NotRun；实际执行后才能写Passed。纯文档无可执行/构建/运行影响才可注明不适用及diff依据，不得写100%。

## 6. MR阶段与交付

- Draft：完整方案已确认、任务文档已先推送、只有一个任务；可列未完成测试和文档核对，CI可在此运行。
- 正式评审：实现完成、单元测试和95%总体覆盖率通过、文档代码一致、适用实验条件满足。
- 合并：正式评审完成、最终代码/集成基线检查有效、具备合并授权。

填写实际分支/提交、MR链接（如创建）、检查证据和限制。不是每个保存文档的请求都需要创建MR。
