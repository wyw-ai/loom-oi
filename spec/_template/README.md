# TASK-NNN：一个可独立验收目标

## 基线与授权

- 工作分支、集成目标、基线完整SHA、关联Issue。
- 用户原指令/已采用需求ID与准确范围；新取舍及依赖（如有）。
- 原始确认在`approval.json`或引用已有确认，不复制/扩大旧批准。

## 目标、边界与方案

用户结果、必要跨模块步骤、对外契约/状态/失败、所引用长期规格；本任务包含与排除项。

## 实施与验收

- 文档先行提交及远端回读。
- 任务步骤与适用阶段门槛，不将尚未到达的门槛前置。
- 完整受管交付单元、单元测试命令/指标/固定排除项，≥95%。
- 契约/集成/竞态/模糊/故障实验及真实环境、判定与原始报告。
- 文档章节→实现符号→验证→结论；安装/部署/恢复和支持矩阵。

## 进度检查点

已完成、未完成、有效验证、最新提交、下一步、阻塞及可独立继续的任务。上下文恢复先读这里，不重复建立同一任务。

## 交付

最终范围、源码/报告/产物入口、实际检查与限制、Issue阶段回执；产品合并/部署授权另按当前明确范围核对。

历史机器清单示例：[task.example.json](task.example.json)、[approval.example.json](approval.example.json)。仅供字段参考，使用前按当前任务及开发规则调整。
