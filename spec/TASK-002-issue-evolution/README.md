## 可验收契约

- R1 历史：Git内保存逐条不可变记录，节点与关系均有稳定ID、来源、范围和记录者；更正通过新关系追加。提供对比指定基线的只追加检查，拒绝覆盖/删除既有记录、重复ID、悬空引用、非法路径与有序关系循环。普通相关/争议关系允许成环。原Issue/评论不自动改写。
- R2 来源：本地来源快照记录哈希，校验实际字节；URL仅是定位不冒充在线已核验。输入可标未知，区分提案、推演、实测与人类决定；人类决定必须具备原确认引用。重复来源分组，不把转述计作独立证据。导入只覆盖能核实的阶段，保留历史缺口。
- R3 检索：每次直接读取当前Git记录，输出输入指纹、覆盖范围与缺口，不维护持久索引。中文短词、英文与已登记机制/别名可检索；结果包含理由、来源和范围。显式机制ID优先于词项相似；未知同义词可能漏检，输出不作新颖性证明。
- R4 复核：给定旧尝试与当前描述/条件，输出相同、改变、缺失条件及复用/重评/继续验证/合理复验/证据不足等提示。缺条件、待核对来源、仅标题相似、证据被挑战或相互矛盾时不作自动否决；报告仍需人核对。允许关键条件变化后的重试；不把旧优先级暂缓或未测当作技术失败。
- R5 关系：按明确的关系语义返回来源链、影响路径与当前未决冲突；一条证据改变只提示复核依赖它的判断，不自动撤销所有相关决定。更正边能以追加记录撤回，冲突不按最新时间自动选赢家。支持按问题生成带中文关系的Mermaid视图，无隐式网络操作。
- R6 验证：用可核实#14/#15记录与明确标记的合成边界案例测试。正常、错误、历史覆盖、来源损坏、换名/条件变化/未知条件/误相似、关系循环等均有有效断言。完整tools非测试Python源码总体行覆盖率至少95%，不以工具覆盖证明产品正确。
- R7 交付：提供CLI用法、数据契约、专业资料取舍、示例/原始验证结果及文档代码对应表；接入已有协作入口，让AI使用工具后核对原文并追加阶段。保留当次输入/代码指纹和失败记录，回复#14。不得把样例检索结果外推成AI推理准确率或生产性能。
