# TASK-007 本地 WebSocket 补丁的完整验证接入

本计划落实已经采用的 [DISC-010-R1](../../docs/decisions/ADR-006-data-leg-liveness.md)，不改变数据腿合同、原产品期限或 95% 门槛。基础源码固定于 `183b34d4066d886042ae3f72db471412ab7b487e`；端点接线仍在实现。本页是适配计划，不是已运行结果，也不提前登记新正式 run。

## 当前缺口

根 `go test ./cmd/... ./internal/...` 不遍历 `third_party/websocket` 的独立模块。根源码清单、时钟准备清单以及复算入口也必须包含这个实际编译输入。仅有根扫描不能替代本地 replace 对应上游版本的漏洞关联；固定 govulncheck 的 JSON/query 成功退出本身不表示没有报告。

64 个上游文件保持原件；本地三个生产文件共 12 条语句，其中原生路径 11 条、JS 不支持路径 1 条。后者已有真实无覆盖运行，但没有自动覆盖输出，不能把它称为已覆盖，也不能从完整交付分母删去。

## 源码和历史闭合

- `run.py`、`clock_run.py` 的来源范围显式加入整个受管 `third_party/websocket`，包括上游原件、测试、许可证、模块文件和本地新增文件；忽略文件检查也覆盖该范围。准备前后与最终回执均绑定同一 Git 源码。
- `verify.py` 的时钟源投影按新清单加入该目录；旧清单没有此目录时保持原投影，不要求旧 run 补造来源。
- 修改当前分析器或它的任一依赖前，逐字归档当前完整分析器及相邻加载依赖。新依赖白名单显式版本化；旧白名单继续可读。19 个既有正式 run 的原件、manifest 和 summary 不改，并用各自记录的分析器精确复算。
- 新 manifest 显式声明唯一的本地补丁验证规格和所需步骤，不能从检测到某个输出推断启用。缺失声明、未知值、漏步骤、过滤用例、源码漂移均拒绝。最终产品固定后才预注册新的正式清单。

## 执行和覆盖率

保留根 unit/race/原扫描命令、各自预算与完整产品库存；增加独立命名步骤，所有命令由 runner 固定，不允许 manifest 传入任意命令或目录。

| 步骤 | 固定范围 | 保留的证据 |
| --- | --- | --- |
| dependency-unit | `go -C third_party/websocket test -json -p=1 -count=1 -covermode=atomic -coverprofile=<绝对路径> ./...` | 完整 Go 事件、原子覆盖原件；不使用 short/run 排除原测试 |
| dependency-race | 同目录完整 `test -json -p=1 -race -count=1 ./...`，CGO=1 | 完整 Go 事件和进程结束/清理 |
| dependency-vet | 同目录 `go vet ./...` | 原 stdout/stderr/退出状态 |
| dependency-staticcheck | 同目录固定 `honnef.co/go/tools/cmd/staticcheck@v0.8.2 ./...` | 原输出，实际问题单独分析，不能静默过滤 |
| dependency-vuln | 固定 `govulncheck@v1.9.0 -json -mode=query github.com/coder/websocket@v1.8.15` | 原 JSON、同一漏洞库输入前后校验、上游来源绑定 |

嵌套模块 unit/race 的执行预算分别 300/600s，vet/staticcheck/query 分别 120/300/120s；这是新增独立工具步骤预算，不续任何既有产品或原用例期限。正式步骤不新增 Go 的 `-timeout` 来放宽原默认限制；开发检查保留它们已经登记的 60/120s watchdog，二者明确区分。

自动覆盖统计保存根 unit 和依赖 unit 的两个原始 profile，并按覆盖块的语句数精确计算，不能以四舍五入后的 `total` 文本判线。完整交付分母为原根 cmd/internal 全部语句，加三个自有补丁文件的 12 条语句；不把未修改的上游代码混入自有分母，也不借第三方目录排除新增代码。原生补丁必须在实际 profile 中完整出现并匹配固定源码和覆盖块；JS 1 条在没有有效自动覆盖前保守记作未覆盖。报告同时给出根、补丁和合并的分子/分母，合并仍须达到 95%。缺 profile、重复/错误归属、漏自有原生文件或不匹配的固定 JS 源码均不能通过。

依赖测试要求全部原生包实际终结且成功；原上游的 `TestAutobahn`（外部套件）和 `TestWasm`（浏览器运行）两个明确条件跳过单列，不能把它们计作通过。新增本地根测试和子测试必须实际通过。额外跳过、无测试输出、缺必要包终结、失败或超时均保留且阻止本步骤通过。CI 工作流同步这些检查，但当前仍按用户决定在本地执行，不能称 Actions 已恢复。

## 漏洞版本映射

保留根产品源扫描；本地替代模块另外以 `UPSTREAM.json` 的固定 module/version/64 文件哈希映射到同一个已登记的官方漏洞库快照。query 只补足已知上游版本匹配，不证明本地新增逻辑无漏洞，也不冒充可达性分析。

解析实际连续 JSON 文档，核对固定工具、模式、唯一查询和完整结束状态。任何返回的 OSV 项目都进入阻断/人工分析，不能把 query 的零退出或 JSON 模式零退出直接判作无漏洞；格式错误、不完整流、版本缺失、错误数据库和输入漂移同样拒绝。真实新增代码另受审阅、单测、竞态和静态检查约束。

采用该映射的工具依据是固定 [govulncheck v1.9.0 使用说明](https://github.com/golang/vuln/blob/v1.9.0/cmd/govulncheck/doc.go)和[同版本 query 实现](https://github.com/golang/vuln/blob/v1.9.0/internal/scan/query.go)。只把其声明的查询行为用于上游版本关联，不从工具能力推导产品安全保证。

## 验证适配器本身

必要反例包括：只跑根包却宣称补丁已测、漏一个补丁覆盖块、把 JS 未覆盖删出分母、用上游大分母掩盖自有不足、过滤/跳过本地用例、错误 cwd/argv、源码哈希或 replace 不匹配、非空 OSV 但退出零、无 JSON 配置或截断输出、不同库快照和前后漂移。新增源码范围同时核验忽略输入和时钟来源；旧 run 逐字重算通过仅证明历史仍可读，不提高其原 verdict。
