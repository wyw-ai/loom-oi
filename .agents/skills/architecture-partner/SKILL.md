# Architecture Partner

读取唯一的完整工作 prompt：[Architecture Partner](../../../docs/prompts/architecture-partner.md)。本技能是项目执行入口，该 prompt 维护完整角色契约，避免复制成两套角色。

## 执行顺序

1. 确认主题、当前分支与授权，读取 [KB 入口](../../../kb/README.md)、当前架构、相关 Issue 和评论。缺少信息时继续可独立开展的推演，明确假设。
2. 蒸馏真实问题与约束，分别标记证据、共同意图、用户决议、AI 建议和未知；不猜缺失媒体。
3. 当轮给出具体解法：职责、对象、交互、状态、正常及失败路径。关键取舍给 2–3 个实质不同候选和明确推荐，不用“去调研”替代方案。
4. 用正常场景与反例推演；说明代价、可逆性和推翻条件。需要实验才能判定的内容写最小验证，不把推演说成实测。
5. 原位更新 Issue，使问题、方案、理由、验证、决策点与后续步骤共同存在。未决不妨碍充分设计，写完不等于已解决。
6. 同步架构与 [决策台账](../../../kb/decisions.md)；可复用事实进入 [证据台账](../../../kb/evidence.md)，提案保留在提案位置。
7. 将工作方式的实际缺陷记入 [经验](../../../kb/lessons.md)，按需改 prompt/模板并验证，不累加无关规则。

## 按需读取

- Issue 工作：[管理规范](../../../docs/issue-management.md)、[当前规划](../../../docs/alpha-issues.md)、[模板](../../../.github/ISSUE_TEMPLATE/problem.md)。
- alpha 设计：[讨论蒸馏](../../../docs/alpha-discussion.md)、[当前架构](../../../docs/distributed-architecture-conclusions.md)、[具体方案](../../../docs/proposals/alpha-solution-design.md)。
- 源码/协议事实：[证据台账](../../../kb/evidence.md)的固定版本及来源；按问题读取原件，不只引用摘要。

## 输出自检

- 若只有问题、研究计划和验收清单，没有具体机制、推荐和反例，继续求解。
- 推荐应说明牺牲什么、何时不适用、什么证据会推翻它。
- Issue 应能独立讨论，包含实质方案摘要和理由；详细设计回链仓库。
- 已授权主题内可以更新成熟问题与方案；新方向、未成熟构想或扩大范围才先列候选。
- 不以文档证明实现，以模型推演证明实测，或以 AI 推荐证明人类同意。本技能不增加合并、关闭、分派或生产实施权限。
