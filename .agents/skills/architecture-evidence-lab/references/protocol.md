# 实验契约与证据等级

## 证据分层

| 等级 | 能支持什么 | 不能支持什么 |
| --- | --- | --- |
| Source | 官方规范/固定源码中的具体行为 | 本项目的实现质量与性能 |
| Model | 状态/数学/纸面推演，自洽性与反例 | 已运行、真实成本与概率 |
| Mechanism fixture | 控制条件下真实执行某个机制/故障 | 完整 OI、真实客户端覆盖、生产 HA |
| Implementation | 特定提交的实现和契约测试 | 未测环境与未覆盖故障 |
| Deployment | 目标拓扑/设备/负载的实测 | 所有部署或未来版本 |

数据与结论都记录等级。一个报告可包含多级证据，必须逐条区分。SHA256 防止静默内容变化，不证明作者独立或结论正确。

## 最小预注册契约

记录问题与上游决定；假设及反例；对照与竞争解释；真实/合成输入及生成器/种子；测量定义、单位与失败判定；样本/重复/次序；软硬件/依赖；隔离和资源边界；输出清单；对哪些 Issue/图/规格有影响。未知阈值写 Unknown，不事后挑有利指标。

实验应有区分度：用可达但业务未就绪区分 TCP 探测与就绪；用副作用已提交而响应丢失区分通道与业务成功。仅验证自己写的 if 分支不能证明架构。

## 隔离

当前受信 fixture 的实际保障：独立子进程/进程组、清洁环境、临时工作目录、127.0.0.1 固定目标、CPU/地址空间/FD/文件大小限制和 wall timeout。父进程记录证据，结束清理所有该进程组子进程。

当前没有 OS 强制的出站网络阻断或文件系统隔离。不要把临时目录当沙箱；不得用此 runner 运行不可信第三方代码、生产操作、真实设备控制或含密钥的试验。更强实验应使用可验证的无外网容器/VM、只读代码/输入挂载和独立资源预算；能力不具备时记录阻塞原因，继续不依赖它的工作。不得为获取隔离擅自修改主机安全设置。

## 完整性与复现

每次生成新 run 目录，不覆盖旧结果。包含 manifest.json、source-manifest.json、environment.json、execution.json、raw.jsonl、stderr.log、summary.json、report.md、SHA256SUMS。原始观测只追加；人工解释另存报告，不改读数。版本化源代码和 run 一起保存；如代码变化使旧 run 无法用当前代码复现，保留对应提交/快照，不用新代码重写旧 summary。

记录退出/超时/缺数据；Inconclusive 不升级成通过。失败重跑只解释修复原因并增加新 run，不删除失败证据。验证 checksum、样本覆盖、计数单位、控制组是否真的生效，以及从 raw 重算 summary。

## 推论审计

分别问：实验做了什么；观测到什么；有哪些竞争解释；支持哪条窄结论；哪些部署变量未覆盖；是否真的能改变选项。语言特性只能生成候选理由，项目推荐应同时考虑协议/可用性/维护/扩展；不能用 Python fixture 的时间推导 Go/Rust 胜负。

重要结果用独立只读审阅，给予原始材料且不预告“应得结论”。审阅发现矛盾要保留并修正，不要求审阅者配合推荐。最终产品取舍仍由人类作出。

## 图文与 Issue 联动

每条 claim 映射到具体产物。若状态细化为接入在线/目标可达/业务就绪/资源忙，状态图、目录描述和监控含义同步；若业务结果不确定，调用时序和重试验收同步；若选型条件变了，部署图和依赖表同步。用户授权关闭边界 Issue 时不把未完成的实现测试一并标完成，测试归属活动主线。

## 强制收尾

运行/重跑/证据复核后，按[实验后闭环](post-round.md)自动继续综合分析；原始报告和命令成功都不是任务终点。分别记录技术判断、方案推荐和人类采用，通过输入指纹追溯证据，不提升整单可信度。
