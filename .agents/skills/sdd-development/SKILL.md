# SDD Development

读取[AGENTS](../../../AGENTS.md)、[开发流程](../../../docs/sdd/development-workflow.md)、当前[任务](../../../spec/README.md)、适用规格与最新Issue。按需读取原始来源；已读且版本未变不重复加载整库。用户指定高能力模型时沿用同一契约，不以模型名称降低验证。

1. 核对用户目标、远端/工作区、已有分支、任务检查点和最新采用。完整明确指令或已采用规格可直接作为本任务授权，避免重新确认同一范围；本地JSON不能证明人类原话。
2. 一个可验收目标一个feature与任务spec，文档先推送回读。必要跨模块代码/测试/文档是同一目标的子步骤；无关功能另立任务。不要直接合入旧feature的过时协作规则。
3. 用`check_sdd --phase implement --require ...`检查本任务需求及依赖；核对适用阶段门槛。G0只放行P1；未到后续阶段时不以G2–G7尚未通过阻挡当前开发。
4. 自主完成实现、内部设计、修复、有效测试和文档更新，不在每次计划、提交、测试或里程碑后询问是否继续。普通调试不制造DISC/ITER。实质新增范围、契约、权限/失败语义或验收变更才在已有Issue提出具体取舍，暂停依赖部分并继续独立工作。
5. 保持完整交付单元≥95%有效单测；竞态、模糊、契约、故障与资源清理由规格决定。正式评审前完成文档→实现→验证核对，绑定真实报告/源码/环境。不降低阈值、缩分母或用无断言测试凑数。
6. 达到产品实验节点时应用[Evidence Lab](../architecture-evidence-lab/SKILL.md)，补齐真实测试与版本化证据适配，保存反证并自动完成综合分析/图文/KB/Issue回写。只在真实证据满足后记录门槛通过并继续下一阶段；不新增逐阶段的人类许可。
7. 遵循既有集成授权与分支保护；未获产品合并授权时保留可评审分支，继续独立任务。不要将生产部署、HA或新产品范围从Autopilot一词中推定出来。
8. 每个重要阶段在任务spec保存可恢复检查点，追加Issue进展并回读；已有明确采用的评论只作结果回复，不重复索取批准。完整交付已确认首版或遇真实不可自行解除阻塞前持续推进，不把P1演示当最终产品。

只在当前开发涉及讨论变更时结合[Discussion SDD](../discussion-sdd/SKILL.md)，不对普通代码循环套用全套讨论审批。遇重复探索风险按既有轻量门控，已有覆盖该重试的授权则引用后继续。规范冲突以当前明确用户指令与最新已采用范围为准，保留差异记录。
