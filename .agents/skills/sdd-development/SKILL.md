# SDD Development

读取[AGENTS](../../../AGENTS.md)、[开发流程](../../../docs/sdd/development-workflow.md)与[结构规范](../../../docs/structure.md)。讨论尚未收束时结合[Discussion SDD](../discussion-sdd/SKILL.md)求解；保持同一原始上下文，不以治理代替产品方案。

1. **确定单一目标**：核对远端和本地分支、集成基线、工作区及用户授权。按共同验收/评审/交付边界划任务；跨模块代码、迁移、测试、文档可作必要子步骤。无关功能另立任务。保留并隔离他人修改，核对任务ID在讨论入口的预占及远端情况。
2. **先保存评审版本**：使用[模板](../../../spec/_template/README.md)准备spec及必要长期文档草案。确认前把完整方案保存在既有讨论入口的固定版本评论或附件，不只放本地、不先建feature。用户在会话确认时保留请求ID、原话和指向的方案上下文。
3. **核对准确确认**：使用唯一approval.json及需求的confirmation_ref，支持Issue评论和用户指令。新增需求指纹绑定明确sdd-scope片段，不把整个共享文件当作本任务。完整明确的指令可直接确认；原则授权不自动覆盖AI新增实质选择，部分确认不放行整个任务。schema合法不证明身份和授权，实际核对原文。
4. **建分支并先推文档**：完整确认后从约定集成分支最新提交创建`feature/<任务ID>-<简述>`，写task.json的分支、基线、需求及文件范围。首笔文档推送回读并与确认版本核对后再实现。已有同任务分支继续使用；集成更新须保留双方规则，解决冲突、更新基线，不能覆盖对方批准或自动刷新确认哈希。
5. **实施与有效单测**：在确认边界内完成必要子步骤；契约/范围/验收实质改变时重新确认相关片段。对固定交付单元完整源码统计单元测试总体行/语句覆盖率≥95%，包含未执行文件，不增设每模块95%要求。不混用E2E覆盖率、不缩分母、不以无断言调用凑数；历史欠账按是否属于本目标决定必要补测或另建前置任务。
6. **按阶段使用MR**：方案已确认且文档先推后可创建Draft，明确未完成检查并运行CI。正式评审前必须实现完成、单测/覆盖率和文档一致性通过；合并还需最终版本检查、评审和合并授权。用户只要求保存规范时不自动创建MR。Draft不替代方案确认，不自动部署。
7. **核对文档与代码**：按最终diff填写文档→实现→验证矩阵，检查接口/默认值、权限/状态/失败、数据、部署示例、图和导航。修错误实现或同步已确认变化，不改需求迁就错误。语义由评审核对，契约测试和可运行示例提供证据。
8. **运行门禁并保存证据**：执行结构检查、所选需求及依赖的SDD implement检查、check_task的draft/review检查，运行对应单测并保留真实原始报告、命令、环境、工具版本、分子/分母与源码/测试/策略指纹。受检文档、代码或目标基线变动后重验。纯文档无运行行为改变才可写覆盖率不适用，不报100%。产品实验门槛独立，工具覆盖率不冒充产品结果。
9. **交付与回应**：推送并回读后报告任务、分支、实际检查、覆盖率口径、文档一致性和限制。处理了用户Issue评论时按[回复规范](../../../docs/issue-management.md#comment-replies)回应原评论并回读。技能实质修改使用独立只读任务验证规则是否可执行、跨阶段能否推进；不仅验证是否机械遵守文字。不得把本地门禁说成远端CI/分支保护已安装。
