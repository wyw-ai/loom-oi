# Issue阶段追加模板

用于已发布Issue的增量评论；初始新单仍用六节模板。规则以[Issue规范](../../../../docs/issue-management.md#append-only)为准，不复制旧全文，不编辑已发评论。按复杂度合并以下小节，但保留前序、实质方案、证据和结果范围。发布前用实际Issue号/下一个阶段号替换占位，链接必须实际存在。

```markdown
### I<编号>-P<序号>｜本阶段变化

阶段类型：方案修订 / 研究结果 / 人类决定落实 / 暂缓 / 更正 / 阶段收束（按实际选择）
触发：原评论链接或准确用户请求；DISC/需求ID。
前序：阶段ID与评论/快照；关系：沿用/修正/替代/验证/反证/承接；准确范围和理由。

**方案与增量**：解决哪个场景；原判断→当前有条件建议；具体机制、正常/失败例、代价与不变项。

**证据与结果**：来源与固定版本，推论/假设/实测分别标明；采纳、否决、暂缓或结论不足的准确范围与依据。涉及人类决定须链接原确认，AI推荐不作采用。

**停止与重启**：为什么现在停/继续；什么新需求、环境、版本或证据变化才重新评估。若为复验，说明新增检验目的。普通进度无新尝试可写“不适用，并沿用前序条件”。

**项目回写与核验**：本轮对loom-oi整体承诺的影响；固定提交/规格版本和当前阅读入口；实际检查、未验证内容和未解决项。旧正文/评论保真是否回读；未完成事项如实说明。

**确认范围**：少量需要判断的新增选择；已明确要求只报告落实。无新增选择时写“供核对改动，无新增产品决策请求”。
```

一个阶段可回应同单多条原评论，但须分别映射；评论已经发出时保存实际ID/链接，再追加阶段发布记录。没有评论ID时标待发布，不虚构链接。重要阶段正文应足够自足，完整技术细节仍在唯一规格位置。
