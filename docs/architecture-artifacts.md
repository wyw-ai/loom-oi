# 架构最终产物与证据联动

“最终产物”指当前对外评审入口，不代表架构已冻结。每轮回复/实验之后检查本表，修改有影响产物；没有影响也记明理由。主工作流保持一个架构上下文，实验室提供证据。

| 触发变化/claim | 权威材料 | 必查产物 | 本轮落实 |
| --- | --- | --- | --- |
| 产品承诺/首批消费者未定，须前置分析 | #10、consumer-scenarios | README、#3、总体图、消费契约、验收 | 增加#10前置，A降为机制验证基线，产品形态待选 |
| 可达≠就绪、探针调度可能拖累其他目标 | LAB-001 raw/report、#2/#7 | 状态图、对象描述、探针职责、统计语义、#8预算 | 增加观测来源/新鲜度、分层状态与独立预算 |
| 响应丢失≠未执行，盲重放有重复副作用 | LAB-002 raw/report、#4/#6 | 调用时序、错误与重试说明、验收 | 在时序图展示“已执行后中断”，不将连接结果写成业务结果 |
| 可用性/维护/扩展进入语言建议 | #8回复、语言比较 | 部署/组件图、能力扩展契约、HA边界、实验列表 | 给Go统一核心推荐及翻转条件；性能/生产HA未证实 |
| #9已授权关闭 | #9用户关闭评论 | Issue索引、决策台账、剩余实验归属 | 按边界决议完成关闭；未做实验归#10/#3/#4，未伪造通过 |

执行顺序：读取最新回复与原始run → 确认claim范围 → 写设计变化及反证 → 更新正文/图源/Issue/KB → 渲染修改图 → 检查图中职责/状态/信任是否与文字一致 → 保存并回读远端。图中的虚线/“候选”不能代替正文决策状态。

实验输入与实际数据保留在experiments；架构图展示职责、状态和时序，不把所有实验节点塞进产品运行架构。新增产品承诺或更强隔离前提须有来源，不从实验夹具自动升级。
