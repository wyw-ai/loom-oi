## 影响关系

| 变更 | 必查产物 | 判定 |
| --- | --- | --- |
| 原始讨论/新反馈 | 项目理念、当前架构、对应Issue、DISC项目收束/需求、KB | 具体机制和反例进入当前规格及Issue阶段增量；保持方案也追加理由 |
| 人类明确采用/撤回 | 决议范围、Issue、架构/模块、图、需求指纹 | 仅覆盖原话范围，采用不等于实验Passed |
| 公共协议/状态/失败边界 | 架构、受影响模块/应用、图源/图、验证向量 | 同一字段/承诺只定义一次，跨模块无冲突 |
| 实验结果/反证 | raw核验→ITER综合分析→结论/方案/图/Issue→适用gate | 窄证据不升级整套产品；晋级在闭环最后 |
| 文档迁移/新增/改用途 | 直接回链、旧锚点、catalog.json/生成目录、SDD指纹 | 原文/证据可追溯，规范主题不重复 |

先做内容/确认范围核对，再运行结构与SDD检查；有影响的图实际渲染/查看，未影响的不为形式重画。保存后回读仓库及Issue。仓库历史由Git保存；Issue正文/评论不会自动进入Git，按追加规范保留真实阶段快照和回链。证据raw与来源快照保留。

## 绘图渠道与视觉标准

1. 每次检查可用且适合任务的专业渠道。展示图、概念插图、视觉素材优先ImageGen；精确拓扑、状态/时序、接口和数据用可确定并校验节点、连线与数值的专业矢量/图表渠道。一次替代不成为永久默认。
2. 新建或更新的标题、节点、连线、图例和状态使用中文，仅保留OIS/OIC等组件/产品/协议名称及必要代码标识。设置中文字体，检查缺字和布局。
3. 逐图校对职责、端点/方向、控制/数据、信任/存储、可选范围及采用/实验状态。避免重叠、交叉和长文本；成功渲染不是视觉合格。
4. 保存DOT等结构源或实际使用的提示词、生成方式、输出哈希与核对记录。未调用ImageGen不得声称已调用；精确信息不让生成模型猜测。
5. 当前图册在[架构图目录](architecture/diagrams/README.md)，历史ImageGen稿用固定Git版本追溯。绘图偏好W9与中文规则W13仍生效。
