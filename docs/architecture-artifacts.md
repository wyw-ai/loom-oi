“最终产物”指当前对外评审入口，不代表架构已冻结。每轮回复/实验之后检查本表，修改有影响产物；没有影响也记明理由。主工作流保持一个架构上下文，实验室提供证据。

执行顺序：读取最新回复与原始run → 确认claim范围 → 写设计变化及反证 → 更新正文/图源/Issue/KB → 渲染修改图 → 检查图中职责/状态/信任是否与文字一致 → 保存并回读远端。图中的虚线/“候选”不能代替正文决策状态。

实验输入与实际数据保留在experiments；架构图展示职责、状态和时序，不把所有实验节点塞进产品运行架构。新增产品承诺或更强隔离前提须有来源，不从实验夹具自动升级。
