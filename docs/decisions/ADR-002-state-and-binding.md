# ADR-002：业务状态外置、准确绑定与运行状态重建

状态：已采用，仅下述边界。确认人plumeink，2026-11-03 14:09:12（+08:00；原记录06:09:12Z）。[原回复](https://github.com/wyw-ai/loom-oi/issues/13#issuecomment-6596770259)：“R5 应用侧承诺：认可业务状态外置、准确绑定及可重建运行状态，相关决策按建议进行收束。”对应H13、DISC-001-R5；回复时参考基线为`aa9db84aa176aa688a4dcf68c11cbc6814b9905b`。

## 决定与执行含义

1. 业务状态由业务提供方、适配器和消费者拥有。命令进程、MCP业务会话、桌面/设备互斥、工作区和业务结果不迁入OI；OI重启不清空、接管或替它们决定恢复。
2. 每次通道准确绑定获准主体和目标及其有效版本。A1→B1、C1→B2不因共用OIC/OIS混淆；失效不静默改投其他实例，不隐式重放原业务载荷。
3. OIC保留完成认证、连接、许可、缓冲/背压及观测所需的有界运行状态。失效/重启后重新认证、对账和建新通道，不把“业务状态外置”误写为完全无状态，不承诺无损续流或恢复旧就绪观测。

正常情况下，业务自己运行并登记获准目标，消费者通过原协议调用；通道中断后业务结果可能未知，应由业务查询/去重/恢复契约判断。这个方向已收束，后续围绕实现与验证，不重复提同一方向选择。

## 候选与代价

相较OI拥有业务账本/会话，采用方案保持能力独立，但业务方承担结果查询、持久去重和资源管理。相较完全无运行状态，保留必要临时状态以实现认证、流控和回收；代价是重启后通道中断、需重认证，新通道不等于业务恢复。具体契约与失败路径由[当前架构](../architecture/alpha-v0.7.md#oic-state)维护。

## 确认边界

本决定不单独批准所有字段名、协议版本、超时/配额/租约参数、K2默认或完整状态机；这些留在DISC-001-R6及#3。双数据库支持/恢复细节和HA由#4及各实验门槛处理。

同一回复要求R1/R2准备实验物料，这授权测试准备；未等同采用完整工具包、全部设备/Pod组合或生产部署。共享冲突资源的具体仲裁实现仍需真实组合验证。V09/V10、G1/G2/G3/G7尚未通过，设计采用不证明产品已实现。
