# loom-oi Autopilot 启动

适用于用户指定的Opus 5.5等高能力模型。此文本由用户发送给开发Agent时启动实施；保存文本本身不代表产品代码已开始。执行依据以[开发流程](../sdd/development-workflow.md)、[当前采用](../decisions/ADR-004-p1-adoption.md)和[阶段门槛](../../experiments/GATES.md)为准。

```text
启动 loom-oi Autopilot，目标是完整交付已确认的首版，不停在计划、骨架或P1演示。
先同步并读取 alpha 的 AGENTS.md、docs/sdd/development-workflow.md、适用skill、KB、最新Issue、采用记录和当前任务检查点；核验G0与本任务需求，已确认事项不再重问。
在授权范围内自主拆成单任务feature，先推spec，再持续实现、调试、测试、更新文档并提交；内部实现细节自行决定。按P1→后续阶段推进，实验通过后自动分析、回写并核验门槛，再继续下一阶段，不逐步询问是否继续。
完整交付已确认的OIS/OIC/oi、R通道、PG/SQLite、授权与目标安全、观测/失败/恢复、安装部署文档及真实支持矩阵；单测≥95%，满足适用CI、产品验收及release-single门槛才可宣布完成。H、HA、未经确认的应用支持和生产部署不默认纳入。
只在改变产品范围、对外契约、权限/失败语义、验收或确需外部资源时，向相关Issue追加具体方案和确认点，暂停依赖部分并继续独立工作；普通失败自行修复，不降低标准或伪造证据。授权在完成任务评审、质量检查及适用门槛并满足分支保护后，将单任务分支合入alpha并继续；不合并main、不部署生产。持续保存可恢复进度，最终汇报真实产物、验证和剩余限制。
```

这不是额外的模型提示链或全新管理系统；无需为每次测试创建审批。若已有同一开发任务，恢复其分支和检查点。首次运行缺真实环境或后续产品取舍时，先推进不依赖该条件的工作并报告准确缺口，不能保证无人干预完成尚未定义的需求。
