# 问题与方案演进：轻量门控与维护边界

当前方案按用户请求`59abbba0-ee87-43e3-baa8-cfc39f82d9bc`收敛为**规范、结构与执行流程**。Git维护仓库现行文档的历史，Issue保留讨论阶段与人类确认，KB索引重要判断及理由。识别到可能重复走旧路时，提交一个针对性的确认Issue；具体执行规则只在[Issue规范](../issue-management.md#revisit-gate)维护。

## 目标与最小结构

目标是让后续讨论能解释“为什么当时这样判断、现在条件是否变了、再投入能学到什么”，同时保留合理重试的空间。流程由当轮人/AI执行，不声称能自动识别全部重复或保证永不犯错。

| 内容 | 唯一维护位置 | 如何使用 |
| --- | --- | --- |
| 真实来源、阶段观点及回复 | 原Issue评论、必要的实际快照 | 核对原意和确认范围，不改写历史 |
| 当前架构/方案/规则 | 相应仓库文档，Git留史 | 讨论后原位整合，避免保存多套当前答案 |
| 重要结论、停止及重试依据 | KB与[演进记录](../../kb/lineage.md) | 用少量有理由的引用串起阶段，不逐句建立节点 |
| 疑似重蹈覆辙的额外确认 | 针对性Issue；已有同一确认单则追加 | 展示旧结论、当前差异、重试价值/成本和选择，确认前只暂停相应重复投入 |
| 本轮问题分工 | [Issue导航](../alpha-issues.md)及当轮汇总Issue | 已定决策归档，未决选择与验证条件分清；汇总不复制决议 |

无需安装脚本、登记机制ID、填写阶段JSON、维护索引或部署图数据库。已有SDD、ADR、实验门槛和代码开发流程继续使用；此处不新增平行审批体系。

## 按真实案例判断

| 场景 | 正确处理 | 防止的偏差 |
| --- | --- | --- |
| Go已由H12确认，尚缺平台/资源数据 | 关闭语言决策单，验证交#11；以后若拟改选Rust，先展示新约束和旧决定并提针对性确认 | 用验证未完成让语言选型一直开放，或把重提当已获准改选 |
| #15再次提出独立中继进程，但路径/负载/故障条件仍不清楚 | 查旧阶段只修正分析次序、没有测量否定隔离；若要重复投入，提交差异及新增价值供确认 | 换个名称重新做同一讨论，或把未测错写成失败 |
| 路径和硬故障目标后来明确，准备再次比较部署 | 说明改变了什么、最小对照和投入边界，按准确确认推进；不因过去暂缓永久禁止 | 把旧经验变成黑名单，或以“条件变了”直接覆盖原决定 |
| 只复用既有决定、修正链接，或执行已明确授权的验证 | 继续既有流程，记录必要依据；不额外建重复确认单 | 把所有工作都变成人类审批 |

未知和来源缺失必须如实写明；没有检索到历史不等于没有历史。文字相似、关系连线和最新时间都不能代替机制与条件判断。是否重试、采用哪种方案与实验是否通过仍是三个问题。

## 本轮纠偏与停止条件

旧图谱比较锚点保留兼容；原r3的三层比较见[固定版本](https://github.com/wyw-ai/loom-oi/blob/326ba0469fe3fc9044aaa17bdd57bf4df6b8aeed/docs/designs/issue-evolution.md#3-图谱要分清三个层次)，不再作为本轮实施目标。

此前r3比较A手工记录、B结构化记录/查询及C专用图服务；随后AI把“仓库级、不要过重”落实为TASK-002脚本并提交[PR #16](https://github.com/wyw-ai/loom-oi/pull/16)。用户指出需要的是门控/结构/流程，说明AI将需求过度实现成了工具工程。工具测试通过并不能证明这项实现必要，也不能代替需求理解。

本轮撤回该PR方案，工具不合入alpha，原分支与评论保留作历史。当前规范不依赖它。以后若确有人工流程无法满足的重复错误或维护成本，应先给具体案例、损失与最小改动，再通过Issue确认是否需要工具；不能因已有代码或投入成本继续推进。

本次只核对规则能否指导真实情形、Issue关闭是否有准确依据和承接。没有测量团队重复探索减少比例，没有新产品实验或运行时架构变更。完整过程与发布结果见[DISC-005](../changes/DISC-005.md)。
