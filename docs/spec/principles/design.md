# 设计原则与取舍

这些原则来自 beta 已确认的产品约束，用于约束后续设计和实现。当前交付范围见[目标与边界](../goals/beta.md)，具体字段规则由[技术参考](../README.md#技术参考)维护。

## 中心定义、通用接入、业务执行分开

OIS 维护消费描述、权限范围、Tool 组合和固定绑定；OIC 负责本地描述、worker 托管、连接及通用参数交付；App 负责目标能力的业务语义和执行状态。OIS/OIC 的通用路径不按 Bash、PowerShell 或其 Action 名加入执行分支。

App 协议独立于实现语言。当前交付使用 Go，不要求第三方 App 链接 Go 包或把业务逻辑写进 YAML。未来能力应先检查是否能沿同样的职责边界接入，而非直接把目标操作塞入 OIS/OIC。

App 也是独立的源码与交付单元：YAML、实现、依赖、构建和测试放在一起，可以离开主工程独立构建，并由既有 OIC 加载。仓库中的 `apps/` 只是收录位置，不能成为第三方扩展必须修改的目录；主工程与 App 通过协议对接，不通过内部包相互依赖。

Filesystem 与 Browser 延续这一分工。访问工作根目录、解释定位器、维护登录状态和生成像素均归 worker。通用图像结果由 Action 显式声明，宿主与中心按协商格式处理；即使业务 JSON 中出现 `image` 或 `content` 键，也沿用原 JSON 语义。预览随本次工具结果交付，完整帧预算和源像素区域决定能交给消费者的内容。[已封板的图像结果要求](../reference/app-runtime.md)

## 配置表达确定关系

当前 Tool 绑定一个通道及一个 App.Action，消费者选择 Tool 后只提供业务参数。多个 Tool 可以通向不同机器；执行链中不增加动态选路、负载均衡、隐式目标切换或业务编排。

runtime 根配置提供默认值，Action 配置提供更具体的覆盖。共享实例和覆盖实例必须有明确语义，不能因为命令文本相同就默默共享状态。具体继承规则见 [App 描述](../reference/app-runtime.md)。

## 参数适配保持轻量

本地 YAML 保留 Action 和基本输入 Schema；减少强制校验不等于省略接入描述。不把中心和本地 Schema 严格相等作为 load 或 Tool 配置的前提，也不引入完整的跨 Schema 验证系统。

调用时才做显式改名、默认填充、基本类型适配及必填检查。能够明确转换的字符串和整数允许传递；对象无法转换成整数等情况在执行前报错。复杂表达式、动态默认、路径及命令业务判断由 App 承担。支持的转换范围以实现契约为准，不承诺任意值都能转换。

## 等待窗口与执行寿命分开

一次 HTTP/MCP 请求无需等待整条命令结束。短执行直接返回输出和退出码；长执行返回句柄，消费者用 `write_stdin` 继续读写。`yield_time_ms` 等待窗口耗尽不是执行超时，空输出也不是失败；服务端请求期限另有取消语义，不能与这个窗口混用。

有限缓冲、输出预算、并发和运行期限构成明确的资源约束。截断必须可见，被省略部分不承诺补读。进程及终端回收须在目标平台验证，不能只凭 worker 已退出就宣称后代已清理。

## 如实表达未知与取消

尚未交付的请求与交付后未获结果的请求不同。后者保留“结果未知”，不自动重跑命令或重复输入；去重只覆盖有限的当前运行周期。

取消一次续读只结束本次等待或未完成输入；已写入的字符无法回滚。网络断开不等于明确取消，Ctrl-C 也不等于进程已退出。重启后不伪造旧执行已恢复。

## 默认易接入，访问选项独立

用户选择的默认是 HTTP/WS、无 Token。HTTPS、管理 Token、通道 Token 和 vMCP Token 分别显式配置；开启其中一个不自动开启其他项。显式配置的凭据缺失或 TLS 配置无效时，不能静默退回匿名或明文。

匿名模式下的 Host/channel ID 核对是配置约束，不是机器身份认证。命令资源限额也不是沙箱；当前没有命令白名单、审批或文件系统/网络隔离策略。配置边界见[配置参考](../reference/configuration.md)。

## 规范、历史与证据分工

`docs/spec/` 维护后续开发使用的当前有效口径；goal-shaping 保留已确认意图和讨论过程；验收报告证明特定配置下已经观察到的行为。设计存在、构建通过或健康检查均不能代替完整使用流程的验收。

更新实现或规范时一并检查相关入口和交叉引用。未来方向明确标为后续范围，不因讨论归档变成已经交付的功能；存在实质冲突时明确记录差异，不以代码现状悄悄替换用户已确认的目标。
