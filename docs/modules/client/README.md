# 消费接入与外部工具适配规格

评审中草案，关联[DISC-001-R1](../../changes/DISC-001.md#requirements)及[#3](https://github.com/wyw-ai/loom-oi/issues/3)。消费者不必登记为OIC；核心客户端只提供发现、认证Open、附着、流和传输诊断。工具适配由外部组件负责，当前未实现；H13已要求为有限、独立部署参考例准备实验物料；正式维护与交付范围由实验后收束，不是官方全工具包承诺。

## 1. 推荐链与责任

Agent工具调用 → 外部工具适配器 → oi客户端/库 → OIS可信中继 → OIC允许目标 → 外部执行服务 → OS进程。原生客户端可以直接使用oi客户端/库；外部适配器不是所有消费者的必经环节。

工具表面将目标选择与业务参数分离。建议外部`exec_argv`接收`exposure_id`、`program`、`argv`数组、`cwd`、允许环境变量引用、超时及输出预算；仅指定shell模式的`exec_script`接收完整`script`字符串。它们是**外部参考契约草图**，不属于OIS API或OIC控制消息。序列化由适配器完成，不让Agent先手写一层`ssh host "..."`再嵌套引号。

`exec_argv`在目标执行服务支持的直接进程API中保持参数边界，不经shell拼接；不能声称所有平台/进程API具有相同转义规则。`exec_script`仍由目标shell解析，引号、管道和变量展开仍有语义；移除外层SSH包裹不消除脚本自身错误。若目标只有SSH，可由外部适配器用固定传输/编码方式承载脚本和参数，具体可逆性与安全性必须验证，不能宣称已经绕过SSH。

## 2. 权限、取消和未知结果

目标ID必须绑定获准Exposure及revision，提供方再检查工作目录、程序/操作权限、凭证和资源预算；不把无条件远程root shell包装成“通道权限”。只将所需业务参数交给提供方，OI诊断不默认记录命令正文、秘密或输出。

外部服务区分接受、运行、已完成、失败、取消确认、结果未知；有业务request_id也不自动得到持久去重。OI返回ChannelInterrupted时，适配器呈现传输失败及业务结果可能未知；禁止因重连自动重发。只有提供方具备已验证的查询/幂等/持久去重契约时才允许对应恢复。取消通道不保证目标进程已停，关闭成功不能显示为业务取消确认。

## 3. 明确取舍和实施范围

推荐A原生通道核心＋一个可选外部参考例，先限定Linux argv/script与结果未知契约；项目是否维护该例由开发者确认后实施。替代①纯通道文档、业务方各自封装，成本最低但重复踩转义/错误语义问题；②核心统一Invoke，统一体验但增加协议/生命周期/权限责任，与H9当前边界不合，不能在本轮默认采用。

先用只读ECS测试服务和固定客户端版本验证参数/输出；再看是否需要持续shell、PTY、文件传输等能力。上述新能力均不从一个SSH案例自动进入首版。

## 4. 验收

详细V01–V04及对照设计见[DISC-001](../../changes/DISC-001.md#validation)。必须分别验证参数字节保真和Agent任务质量；前者通过不能证明后者改善。真实Mac/ECS/客户端、目标程序与OI路径尚未就绪，均为未运行/受阻；本轮完成[R1准备物料](../../../experiments/materials/README.md)与记录夹具检查，尚无真实产品数据。

## 外部工具契约

完整设计示例与取舍见[远程执行链](../../designs/application-paths.md#remote-exec)、[应用控制链](../../designs/application-paths.md#app-control)。以下是外部适配契约，不增加OI核心消息。

| 输入/行为 | 消费适配责任 | 提供方权威/结果 |
| --- | --- | --- |
| target别名、expected_revision | 解析获准Exposure且本次固定；不得沿用隐含上次目标或接受任意URL | 返回实际目标/业务实例；变更后重新发现与授权，不改投其他环境 |
| argv或script、cwd、env引用 | 模式显式；不拼第二层SSH字符串；每次调用声明环境，输出有界 | argv走支持的直接进程接口；script仍按目标shell解释；业务权限独立校验 |
| operation_id、完成/失败/未知 | 展示传输与执行两个状态；取消无确认不能当已取消 | 进程/结果/持久查询与去重由提供方实现；不支持时明确Unknown且不盲重试 |
| device/session/app/instance与观察ID | 使用真实工具的等价字段；拒绝把标签当权限 | 共享输入域互斥、动作时复核目标、效果核验；失效画面需重观察 |
| MCP传输与业务身份 | 锁定真实版本组合，原生可用则不重复封装；stdio bridge独立部署 | bridge拥有子进程/会话；端点身份、Origin和业务认证不能由loopback绕过 |

对于共享冲突输入域，互斥默认按桌面会话或设备，不能按Channel；独立资源和服务内句柄不强制套此仲裁协议。过期租约只能撤销继续操作资格；旧动作未静止时不能交接输入域。长任务、PTY、持久去重与批动作均是有独立代价的外部扩展，不从通道成功推定已提供。

## 业务会话与共享资源

客户端在新OI通道上按原生协议处理握手/会话，不把Channel ID当业务session，不因重连重放未知操作。应用互斥由外部服务发放绑定主体/资源/实例的所有权；拿到所有权后重新观察，有限规划/动作/核验，释放前确认无在途动作。Busy/资源隔离是提供方业务结果，不伪装成OI通道错误。例外、超时、仲裁重启及支持边界见[架构§5.6](../../architecture/alpha-v0.7.md#resource-arbitration)。

## 准确目标与业务句柄

A/C分别选择B1/B2并核对实际目标；不共享隐含“当前目标”。独立端点各用获准Exposure；同一服务的tab/任务句柄由原协议携带及校验，OI不理解其业务ID；真正共享冲突才走外部仲裁。一个业务会话可使用多个Channel，原协议也可在同一流多次交互；不由OI按session创建进程/设备。B1失败明确失败，不回退B2或重发。详见[三类路径及反例](../../architecture/alpha-v0.7.md#target-binding)。

## 路径变化与消费者体验

客户端对[项目整体体验](../../concept/loom-oi.md#promises)负责：展示获准目标、准备/已打开/中断及业务未知的区别。[H候选](../../designs/ois-control-relay.md#channel-evolution)只对新Open及准备阶段研究路径选择/回退，不能暗示已经打开的字节流无损迁移。重建Channel仍需新授权且不自动重发业务；路径探测只能使用验证后的候选端点并受总预算约束。当前R接入契约保持，尚无H实现或兼容数据。

本轮采用范围以[ADR-003](../../decisions/ADR-003-first-release-boundaries.md)为准：C1默认/C2首版支持已定，C3只确认H研究边界；具体协议/状态竞争/存储实现未随之全部批准。开发缺口与联合观察见[准备度评估](../../evidence/implementation-readiness-004.md)，不能以方向采用替代G0。

v1/P1的详细契约已收束为[P1规格包](../../architecture/p1/README.md)（B1–B4，待整体确认）；本页的职责与边界不变，确认前不作为实现依据。
